# Install requirements.txt FIRST, then this file — on the Raspberry Pi only.
# These are Linux/Pi-specific (I2C, GPIO, camera stack) and will fail to
# build on Windows/macOS dev machines. Every sensor module that uses one of
# these falls back to a mock automatically if it isn't installed, so the
# main pipeline runs fine on a dev laptop without any of this.

spidev      # src/output/leds.py's APA102 strip driver, over the Pi's hardware SPI0
            # (needs SPI enabled: sudo raspi-config -> Interface Options -> SPI)
gpiozero    # mini PIR sensor
lgpio       # gpiozero pin-factory backend required on Raspberry Pi 5 —
            # RPi.GPIO (gpiozero's default) does not support the Pi 5's
            # GPIO chip
smbus2      # I2C bus access, used by both the hand-rolled MAX30102 driver
            # (src/sensing/heart_rate.py — no dedicated pip package exists
            # for the DFRobot Gravity/Fermion module) and multisensor.py
pimoroni-bme280   # Pimoroni Multi-Sensor Stick (PIM745) — temperature/
                  # humidity/pressure; import name is `bme280`
ltr559            # Pimoroni Multi-Sensor Stick (PIM745) — light/proximity

# MLX90640 (central thermal motion camera, src/sensing/motion.py) is
# intentionally NOT listed here: Pimoroni's MLX90640 Python binding isn't
# a pip package, it's a compiled C extension built from source:
#   git clone https://github.com/pimoroni/mlx90640-library
#   cd mlx90640-library && make && sudo make install
#   cd python/library && make build && sudo make install
# src/sensing/motion.py treats `import MLX90640` as a best-effort optional
# import, same pattern as every other sensor's optional hardware library.
